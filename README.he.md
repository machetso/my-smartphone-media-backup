# My Smartphone Media Backup

גיבוי מאומת ומצטבר של תמונות וסרטונים מטלפון Android לכונן חיצוני אחד או יותר,
ממוין לפי שנה וחודש, עם דוח לאחר כל הרצה.
Python 3.8 ומעלה, פועל ב-Linux וב-Windows. הממשק הגרפי דורש PySide6; גרסת
הטרמינל אינה דורשת חבילות נוספות.

## הורדה

תוכנות מוכנות להפעלה עבור Linux ו-Windows נמצאות ב
[דף ה-Releases](../../releases) - אין צורך בהתקנת Python.
Windows: יש להוריד את `My-Smartphone-Media-Backup-v….exe` וללחוץ עליו לחיצה כפולה (או את ה-`.zip` עם
ה-README והרישיון); Linux: את ה-`.tar.gz`.
מה חדש – ראו [CHANGELOG.md](CHANGELOG.md).

**עדכונים:** בהפעלה התוכנה בודקת אם יצאה גרסה חדשה יותר (פעם ביום; ניתן
לכבות זאת בהגדרות) ומציעה **עדכן עכשיו** או **לא עכשיו**. *עדכן עכשיו* מוריד את הגרסה
החדשה, בודק שהיא חתומה במפתח השחרור של הפרויקט, מחליף את התוכנה ומפעיל אותה מחדש
– ההגדרות, הכוננים, הטלפונים וההתאמות נשמרים. אם הגרסה החדשה לא עולה, הגרסה הישנה
מוחזרת אוטומטית. (אם התוכנה הופעלה מקוד המקור: יש לעדכן במקום זאת עם `git pull`.)

**הוצאת גרסה (מתחזק):** לדחוף את התגית ← GitHub Actions בונה את טיוטת ה-release ←
`python3 tools/sign_release.py sign vX.Y.Z` במחשב של המתחזק (מוסיף את הקובץ החתום
`update-manifest.json`; המפתח הפרטי לעולם לא מגיע ל-GitHub) ← לפרסם את ה-release.

## הפעלה מקוד המקור

**ממשק גרפי** (דורש PySide6):

```
./start-linux.sh                   # Linux (uses the project's .venv, PySide6 is already installed there)
start-windows.pyw                 # Windows: double-click (after: py -m pip install PySide6)
```

**מסך הפתיחה:** **הטלפונים שלך** – רשומה אחת לכל גיבוי (למשל *Sam's Pixel 10 Pro*,
*Kim's Galaxy A55*) עם תאריך הגיבוי האחרון שלו וכפתור **עדכון גיבוי** משלו,
שזמין כאשר בדיוק הטלפון הזה ואחד הכוננים שלו מחוברים (אותן תיקיות ואותם כוננים,
רק תמונות וסרטונים חדשים). גיבויים שנעשו לפני שהרשימה הזו הייתה קיימת נמצאים בכוננים
המחוברים. *בחירת הכול* / *הסרה מהרשימה* מסתירים טלפונים (הגיבויים שלהם נשארים בכוננים). למטה:
**גיבוי חדש…** (טלפון אחר, או תיקיות / כוננים אחרים), **הגדרות גיבוי…** ו-
**ניהול גיבויים…** (הלשוניות שלהלן).

**☰ תפריט** (בפינה השמאלית העליונה של מסך הפתיחה, כבר בהפעלה הראשונה): **שפה**, **מדריך** (הטקסט הזה, בשפה שנבחרה), **הגדרות התוכנה…** ו-**אודות**.

**הגדרות גיבוי** (דף משנה):

* **חיבור הטלפון** – התוכנה **תמיד משתמשת בחיבור המהיר ביותר שהיא מוצאת**; אין צורך
  לבחור. הסקירה מציגה את המהירות של כל דרך חיבור, הדרך שבשימוש מסומנת, והיומן
  מציין אם היא המהירה ביותר ומה היה מהיר יותר. אם הטלפון מופיע עם ניפוי באגים ב-USB
  בכבל בזמן שהוא מחובר דרך Wi-Fi, התוכנה עוברת לכבל
  מעצמה. **מציאת החיבור המהיר ביותר** בודקת את הכבל, את ה-Wi-Fi ואת ה-Bluetooth ומציגה
  מה זמין.

  **תצוגה פשוטה:** רק מצב החיבור, וכשזה עוזר – טיפ מתחתיו. טלפון שעדיין אין לו גיבוי: הטיפ ממליץ
  על כבל USB עם ניפוי באגים ב-USB (הגיבוי הראשון מעתיק את כל התמונות והסרטונים). טלפון בכבל בלי
  ניפוי באגים ב-USB, או מחובר דרך Wi-Fi / העברת קבצים: הטיפ מציין כמה מהיר יותר ניפוי באגים ב-USB
  – *איך מפעילים ניפוי באגים ב-USB…* פותח את המדריך צעד אחר צעד (ראו למטה), *המשך בלי (העברת קבצים
  איטית יותר)* משתמש בהעברת הקבצים הרגילה של הטלפון. סמנו **הגדרות חיבור מתקדמות** כדי לראות את
  סקירת המהירויות, את כל כפתורי החיבור ואת *כיבוי … אחרי הגיבוי*.

  | חיבור | מהירות |
  |---|---|
  | כבל USB + ניפוי באגים ב-USB (מופעל על ידי אפליקציית הטלפון, או ידנית) | 45–50 MB/s (USB 3), כ-20–30 MB/s (USB 2) |
  | כבל USB, העברת קבצים רגילה (MTP – רק לפי בקשה) | 10–20 MB/s |
  | Wi-Fi: אפליקציית הטלפון או ניפוי באגים אלחוטי | 10–40 MB/s, תלוי ב-Wi-Fi |
  | Wi-Fi ישירות למחשב הזה (ללא נתב) | 10–30 MB/s |

  *הפעלת ניפוי באגים ב-USB (בפעם הראשונה)…* הוא מדריך צעד אחר צעד: הוא קורא את דגם
  הטלפון שבכבל (עובד עוד לפני שניפוי הבאגים ב-USB מופעל), כולל את השלבים עבור Pixel, Samsung,
  Xiaomi / Redmi / POCO, OnePlus / OPPO / realme, Motorola, Huawei / Honor, Sony ו-Nothing, ו-
  *חיפוש ברשת עבור הטלפון הזה* עבור כל טלפון אחר. Android דורש זאת פעם אחת באופן ידני – אף תוכנה
  לא יכולה להפעיל ניפוי באגים ב-USB לפני כן.
  **אפליקציית הטלפון מפעילה אותו:** בחיבור הראשון עם ניפוי באגים ב-USB התוכנה מציעה להתקין
  את אפליקציית הטלפון *My Media Backup* ולתת לה את ההרשאה להפעיל ולכבות ניפוי באגים ב-USB (ההרשאה של Android
  `WRITE_SECURE_SETTINGS`, ניתנת דרך הכבל – האפליקציה לא יכולה לקבל אותה בעצמה). מאותו
  רגע: לפתוח את האפליקציה ← **לאפשר גיבוי בכבל** ← לחבר את הכבל. לאחר כל גיבוי המחשב
  מכבה שוב את ניפוי הבאגים ב-USB (או את ניפוי הבאגים האלחוטי) (*לכבות … לאחר הגיבוי*, מופעל
  כברירת מחדל). רק ניפוי הבאגים ב-USB נכבה; אפשרויות המפתחים נשארות.

  **כללים לכיבוי ניפוי הבאגים** (אפליקציית הטלפון אוכפת אותם גם אם המחשב כבר לא זמין):
  1. גיבויים דרך Wi-Fi רצים בדרך כלל דרך אפליקציית הטלפון כשניפוי הבאגים כבוי; ניפוי באגים אלחוטי
     רק עבור טלפונים בלי האפליקציה.
  2. חיבור אחד לכל גיבוי: דרך הכבל ← ניפוי הבאגים האלחוטי נכבה בהתחלה;
     דרך האפליקציה ב-Wi-Fi ← ניפוי הבאגים ב-USB נכבה בהתחלה.
  3. אפליקציית הטלפון לעולם לא מפעילה ניפוי באגים אלחוטי.
  4. 5 דקות אחרי *לאפשר גיבוי בכבל* בלי שהתחיל גיבוי ← כבוי (ספירה לאחור בטלפון).
  5. במהלך גיבוי המחשב אומר "אני עדיין כאן" כל 30 שניות; אם אין שום אות במשך 2 דקות ← כבוי.
  6. מיד לאחר הגיבוי המחשב מכבה אותו (ומסיים את מצב הגיבוי בטלפון).

  **זיהוי מאובטח של הטלפון:** בעת ההתאמה אפליקציית הטלפון יוצרת מפתח בשבב
  האבטחה של הטלפון; המחשב שומר את טביעת האצבע שלו. לדגם, למספר הסידורי או לשמות אין
  אמון לעולם – כל חיבור בודק את המפתח הזה (TLS עם התעודה הנעוצה) לפני שהסוד של
  המחשב נשלח.
  * **כבל:** כל עוד האפליקציה פועלת, המחשב מגיע אליה דרך הכבל (`adb forward`) ו-
    בודק את המפתח – הסטטוס מציג אז *מאומת*. בפעם הראשונה: המחשב מתקין את האפליקציה,
    פותח אותה ומבקש לבצע התאמה דרך הכבל; יש להקיש **התאמה** בטלפון (אין צורך בקוד,
    הכבל הוא ההוכחה).
  * **Wi-Fi:** האפליקציה מכריזה על עצמה באופן אנונימי: שם אקראי וקוד שמתחלף כל
    10 דקות, שרק מחשב מותאם יכול לזהות (HMAC של סוד ההתאמה). זרים
    באותה רשת לא יכולים לראות איזה טלפון זה ולא לעקוב אחריו.
  * **Bluetooth (מוצא אחרון, רק לאיתור הטלפון):** אותו קוד מתחלף יחד עם כתובת
    ה-Wi-Fi של הטלפון (מוצפנת) באות Bluetooth LE. אם המחשב יכול להגיע לכתובת הזו הוא
    מתחבר דרך Wi-Fi; אחרת הוא מודיע על כך. **שום קובץ לא נשלח אף פעם דרך Bluetooth.**
    דורש את חבילת Python בשם `bleak` (ב-requirements.txt) ואת ההרשאה "מכשירים בקרבת מקום"
    בטלפון.
* **תיקיות בטלפון** – **מצלמה** מוסיפה את תיקיית המצלמה הרגילה של Android‏ `DCIM/Camera`;
  *בחירת תיקיות…* מציגה את התיקיות שבטלפון (צילומי מסך `Pictures/Screenshots`, ב-Samsung
  `DCIM/Screenshots`, WhatsApp‏ `Android/media/com.whatsapp/WhatsApp/Media`, `Movies`, `Download`
  …) או מאפשרת להקליד תיקייה (*בחירת הכול* / *ביטול הבחירה*); *הסרה*.
  **שמירת מבנה התיקיות של הטלפון** (אפשרות): קבצים מתיקיות שאינן תיקיית
  המצלמה נשמרים בגיבוי באותן תיקיות, למשל `Sam/Pixel 10 Pro/Pictures/Screenshots/`;
  תיקיית המצלמה תמיד ממוינת לתיקיות שנה/חודש. קבצים שכבר גובו נשארים
  במקומם; קבצים זהים עדיין נשמרים פעם אחת בלבד.
* **יעדי גיבוי** – רשימת כונני היעד; שמות תיקיות ארוכים ניתנים לגלילה
  לצדדים (השם המלא מופיע כתיאור צץ).
  יש לסמן כונן אחד או יותר. *הוספת כונן…* מציגה את הכוננים החיצוניים המחוברים, כולל כוננים
  שמחוברים פיזית אך עדיין לא מחוברים למערכת הקבצים (Linux: הם מחוברים בלחיצה אחת, ללא סיסמה).
  *הוספת תיקייה…* פותחת בורר תיקיות. כונן מסומן שמחובר פיזית אך לא מחובר למערכת הקבצים מחובר
  אוטומטית כשהגיבוי מתחיל. תצוגה מקדימה מראה בדיוק לאן הקבצים יגיעו. הטלפון מזוהה אוטומטית ברגע
  שהוא מחובר דרך ADB. הרשימה מציגה רק את הכוננים ששימשו בעבר
  עם הטלפון הזה (והבעלים), כבר מסומנים; טלפון בלי גיבוי מתחיל עם רשימה ריקה. *הוספת כונן…* מציעה
  גם את תיקיות הגיבוי ששימשו עם טלפונים אחרים.

**אף פעם לא הטלפון הלא נכון.** כל תיקיית גיבוי זוכרת את הטלפון שלה ב-`.phonebackup/phone.json`
(דגם, המספר הסידורי של הטלפון, מזהה המפתח של אפליקציית הטלפון; בגיבויים ישנים יותר התוכנה קוראת
אותם מהדוחות). בלחיצה על *התחלת גיבוי* הטלפון המחובר מזוהה בזמן אמת
ומושווה: מספר סידורי או מפתח שונים ← **נדחה, שום דבר לא מועתק**. אם אפשר להשוות רק
את הדגם, או שהדגם לא תואם לשם הגיבוי, יש לאשר זאת. ממש לפני
הקובץ הראשון הטלפון מזוהה פעם שנייה (טלפון שהוחלף עוצר את הגיבוי). טלפון
שמתחבר לעולם לא מחליף את שם הסמארטפון שהגדרת, וכל עוד טלפון מחובר בכבל USB לא נלקח
טלפון אחר דרך Wi-Fi. האישור מציג את החיבור, ואם הוא אינו
המהיר ביותר, גם איך להפוך אותו למהיר יותר (כבל + ניפוי באגים ב-USB; כבל USB 3 במקום USB 2).

ל-**ניהול גיבויים…** יש ארבע לשוניות:

* **כונן ישן / טלפון ישן** – גיבוי התמונות והסרטונים של כונן קשיח ישן או של טלפון ישן
  כמו גיבוי טלפון. שתי דרכים:
  * *הוספה לגיבוי קיים* – מוסיפה גיבויים ישנים או כל תיקייה שהיא (תמונות, סרטונים, RAW מעורבבים,
    תיקיות מקוננות, כפילויות) לאחד הגיבויים שלך.
  * *גיבוי חדש (טלפון ישן או כונן ישן)* – מקבל גיבוי משלו (למשל “Galaxy S7 - Sam” או
    “Old drive - Sam”): יש להזין שם ובעלים ולסמן את כונן (או כונני) היעד.

  יש להוסיף תיקייה אחת או יותר (למשל ההעתק של הטלפון הישן ושל כרטיס ה-SD שלו, או תיקיות התמונות
  של הכונן הישן) וללחוץ על *בחירת תיקיות לייבוא…*: כל תיקייה שיש בה קבצים מוצגת עם מספר
  התמונות / הסרטונים / הקבצים האחרים שבה; נתוני אפליקציות, מטמונים, תמונות ממוזערות, אשפה ותיקיות
  מוסתרות לא נכללים. יש לסמן את התיקיות ולבחור לכל אחת:
  * *למיין לתיקיות שנה/חודש* – התמונות והסרטונים ממוינים לפי תאריך בדיוק כמו בגיבוי טלפון
    (`2019/19.07`, RAW ← `2019/raw/19.07`).
  * *להשאיר את התיקייה כמו שהיא* – התיקייה מועתקת 1:1 עם השם והנתיב שלה לרמה העליונה של
    הגיבוי (למשל `Urlaub Italien 2019/Tag 1/`). כל תיקייה מיובאת עם הקבצים שלה בלבד, תתי-התיקיות
    שלה מופיעות בשורות נפרדות – יש לסמן גם אותן כדי לשמור על כל עץ התיקיות.

  בטלפון ישן מוצע למיין את תיקיות המצלמה, ולהשאיר כמו שהן את תיקיות התמונות/הסרטים/ההורדות
  הרגילות; תיקיות של אפליקציות מסרים וצילומי מסך לא מסומנות מראש. כל קובץ מגובב במקור ומאומת
  לאחר הכתיבה, קבצים זהים נשמרים פעם אחת בלבד (גם מול מה שכבר נמצא בגיבוי), התיקיות הישנות רק
  נקראות. קבצים שדולגו מפורטים בדוח “ייבוא <name> <date>”. (ייבואים שנעשו לפני גרסה 0.9.8.3
  שמו תיקיות שנשמרו כמו שהן תחת `Year/other/pictures | movies | other-files/` – הן נשארות שם.)
* **אחסון משני (ייצוא)** – יש לבחור את הגיבוי, כונן שני או **Google Drive** ואת סוג
  הייצוא (*אוטומטי – סב-אב-בן* כברירת מחדל). ייצואים קודמים מוצגים ברשימה; ניתן לנקות
  ייצואים ישנים (רק אחרי אישורך). ראו *אחסון משני* בהמשך.
* **שחזור** – יש לבחור את מערכת הייצוא (בכונן או ב-Google Drive), את המצב ואת תיקיית
  היעד.
* **הגדרות** – נתיב adb (בדרך כלל ריק = נמצא אוטומטית), זמן המתנה, fsync, השארת
  המחשב ער. ריחוף מעל הגדרה מציג הסבר.

**למה ADB?** ‏ADB (Android Debug Bridge, כלי ה-USB של Google עבור Android) הוא הדרך המהירה והבטוחה:
בערך 45–50 MB/s בכבל USB 3 (נמדד עם Pixel 10 Pro), בעוד ש-MTP - מצב
"העברת קבצים" הרגיל - מגיע בדרך כלל ל-10–20 MB/s. עם ADB כל קובץ גם נבדק עם
SHA-256 בטלפון עצמו. אם ADB לא עובד, האפליקציה עוברת ל-MTP ומודיעה על כך.

**להשאיר את המחשב ער:** בזמן שגיבוי, ייבוא, ייצוא או שחזור רצים, המחשב
נמנע ממעבר למצב המתנה (מופעל כברירת מחדל, ניתן לכבות תחת *הגדרות*). הגדרות החשמל
עצמן אינן משתנות – החסימה מסתיימת אוטומטית עם המשימה, גם אחרי קריסה.
Linux: מצב המתנה, השהיה בזמן חוסר פעילות, סגירת המכסה וכיבוי רגיל נחסמים (logind
inhibitor), וגם הטיימר של שולחן העבודה לחוסר פעילות מושהה (D-Bus `org.freedesktop.ScreenSaver`
inhibit, כמו שנגן וידאו עושה - נחוץ ב-COSMIC ובשולחנות עבודה אחרים שמשהים את המחשב
מעצמם אחרי חוסר פעילות). לכן בזמן שמשימה רצה המסך נשאר דלוק.
Windows: שינה בגלל חוסר פעילות נמנעת ו-Windows שואל לפני כיבוי;
סגירת המכסה וכפתור ההפעלה עדיין פועלים לפי הגדרות החשמל של Windows.

**סמל בשולחן העבודה (Linux):** `./install-linux-desktop.sh` מוסיף סמל הפעלה לשולחן העבודה ול-
תפריט האפליקציות (יש להריץ אותו שוב אחרי העברת התיקייה, `--remove` מסיר אותו שוב).
הסמלים נבנים מ-`assets/PhoneBKP_Logo.webp` באמצעות `.venv/bin/python tools/make_icons.py`.

סרגל ההתקדמות, המהירות, הזמן שנותר והיומן נמצאים בתחתית, עם *ביטול* (עוצר
אחרי הקובץ הנוכחי), *פתיחת הדוח* ו-*פתיחת תיקיית הגיבוי*.

**גרסת טרמינל** (ללא חבילות נוספות): `python3 smartphone_media_backup.py --cli`
או ישירות `smartphone_media_backup.py backup | export | restore | settings`.
אם PySide6 חסר, `smartphone_media_backup.py` מפעיל את גרסת הטרמינל אוטומטית.

## התוצאה בכונן

```
PhoneBackups/
└── Sam/                                     ← one folder per owner
    └── Pixel 10 Pro/                        ← the backup of this phone
        ├── Logs/                            ← reports and logs
        │   └── Backup Pixel 10 Pro Sam 2026-11-02.txt / .html / .csv
        ├── 2026/
        │   ├── 26.01/  …  26.12/            (photos + videos of each month)
        │   ├── raw/26.01/ …  raw/26.12/     (only if RAW/DNG files exist)
        │   └── other/pictures|movies|other-files/<original folder>/   (only old phone imports)
        └── .phonebackup/index.sqlite        ← what is already backed up (do not delete)
```

* שם תיקיית החודש = שנה + חודש: `26.02` הוא פברואר 2026. גיבויים של גרסאות קודמות
  (`02.February-photos` / `02.February-videos`) מומרים לפני הגיבוי או הייצוא הבא – קודם התוכנה
  מציגה את תיקיות החודש הישנות ויש לבטל את הסימון בתיקיות ש**שומרות על השם והמבנה הישנים** (הן
  לעולם לא משתנות). הבחירה חלה על כל כונן ועל Google Drive; קבצים רק מועברים, לעולם לא נמחקים.
  התיקיות שלך ותיקיות עם "שמירת מבנה התיקיות" לעולם לא משתנות.
* תיקיות שנה וחודש נוצרות רק כשקובץ נכנס אליהן - בלי תיקיות ריקות.
* חודש = תאריך הצילום מנתוני המטא של התמונה/הסרטון ← אחרת שם הקובץ
  (`PXL_20261102_…`) ← אחרת תאריך הקובץ.
* תמונות בתנועה (`*.MP.jpg`),‏ HEIC,‏ PNG, … נחשבים לתמונות; DNG וקובצי RAW אחרים נשמרים ב-`raw/`.
* תיקיית גיבוי = בעלים / טלפון (`Sam/Pixel 10 Pro`). גיבויים של גרסאות קודמות
  (`Pixel 10 Pro - Sam`) מועברים לשם אוטומטית; אם שניהם קיימים, הם ממוזגים – שום דבר לא
  נדרס או נמחק.
* דוחות (`.txt` / `.html` / `.csv`) והיומן של משימה שהסתיימה בלי דוח נשמרים בתיקייה `Logs`
  ליד תיקיות השנים. דוחות של גרסאות קודמות מועברים לשם אוטומטית לפני הגיבוי, הייבוא או
  הייצוא הבא.
* לדוח שני באותו יום מתווספת השעה לשם.
* שום דבר לא נמחק לעולם: לא בטלפון ולא בגיבוי.
* אותו שם אבל תוכן שונה ← הקובץ החדש נשמר בשם `name_1.jpg`. תוכן זהה
  נשמר פעם אחת בלבד.

## בטיחות

* **טלפון ← מחשב:** עם ADB, הטלפון מחשב בעצמו את ה-SHA-256 והוא מושווה
  לנתונים שהתקבלו. עם MTP זה לא אפשרי, והדוח מציין זאת.
* **מחשב ← כונן:** כל העתק נכתב בכוח לדיסק, נקרא בחזרה וה-SHA-256 שלו מושווה.
* קבצים נכתבים כקבצים זמניים ושמם משתנה רק אחרי הבדיקה. גיבוי שנקטע
  לעולם לא משאיר חצאי קבצים; ההרצה הבאה פשוט ממשיכה.
* שני כוננים (או יותר) נכתבים **בו-זמנית**. הטלפון נקרא פעם אחת בלבד.
* המקום הפנוי נבדק קודם. אם כונן נכשל או מתמלא, הגיבוי ממשיך בכונן
  השני והדוח מציג זאת באדום.

## הגדרת ADB (פעם אחת). כך הטלפון מוכן לשימוש תוך כ-2 שניות במקום להמתין ל-MTP

**בטלפון**

1. הגדרות ← מידע על הטלפון ← להקיש 7 פעמים על *מספר Build* (מצב מפתחים מופעל).
2. הגדרות ← מערכת ← אפשרויות למפתחים ← להפעיל את **ניפוי באגים ב-USB**.
3. לחבר את הטלפון, לבטל את נעילתו ולאשר את *לאפשר ניפוי באגים ב-USB* עם
   **לאשר תמיד מהמחשב הזה**.

**Linux (Pop!_OS / Ubuntu)**

```
sudo apt install adb
adb devices          # should show your phone as "device"
```

**הכי פשוט (Windows ו-Linux):** *הגדרות ← הורדת ADB…* מוריד את ה-platform-tools
הרשמיים של Google ישירות מ-Google לתיקייה של האפליקציה עצמה (Windows:
`%LOCALAPPDATA%\phonebackup\platform-tools`, Linux: `~/.local/share/phonebackup/platform-tools`)
ומגדיר את הנתיב - בלי התקנה, בלי הרשאות מנהל. adb לא מצורף לאפליקציה כי
הרישיון של Google אינו מתיר להפיץ אותו הלאה.

**Windows (ידנית)**

1. להוריד את *SDK Platform-Tools for Windows* מ-
   https://developer.android.com/tools/releases/platform-tools
2. לחלץ אותו כך שהתיקייה `platform-tools` תהיה **ליד `smartphone_media_backup.py`** (נמצאת אוטומטית),
   או להזין את הנתיב ל-`adb.exe` תחת *הגדרות*.
3. Google Pixel: אם הטלפון לא נמצא, יש להתקין את *Google USB Driver*.

אם ADB לא עובד, התוכנה מציגה אזהרה ברורה ועוברת ל-**גיבוי חלופי דרך MTP**:

* Linux: הטלפון מחובר אוטומטית דרך gvfs/`gio`. יש לבחור *העברת קבצים* בהתראת
  ה-USB של הטלפון.
* Windows: דורש פעם אחת `py -m pip install pywin32`. לאחר מכן Explorer מעתיק את הקבצים.
  זה איטי, ולא נבדק על חומרה אמיתית במהלך הפיתוח (ראו בהמשך).

## אפליקציית טלפון (Wi-Fi, ללא ניפוי באגים ב-USB)

**הגדרת אפליקציית הטלפון…** מציגה קוד QR. יש לסרוק אותו במצלמת הטלפון: הדף (שמוגש על ידי
המחשב הזה) מציע **1. הורדת האפליקציה** (לפתוח את הקובץ, להקיש *התקנה*) ו-**2. חיבור האפליקציה**.
הטלפון והמחשב מציגים אותו קוד בן 6 ספרות - יש לאשר אותו **בטלפון ובמחשב**
(הטלפון מוסר את המפתח שלו רק אחרי ההקשה שלך שם). מתבצע פעם אחת. התאמה דרך כבל ה-USB
עובדת באותה דרך: שני המסכים מציגים קוד, יש להקיש *התאמה* בטלפון רק אם הקודים זהים.

דרך הכבל התוכנה יכולה גם להתקין את האפליקציה בעצמה – היא תמיד **שואלת קודם** ו-
מסבירה איזה טלפון, איזו גרסה, למה ומה בדיוק יקרה; שום דבר לא מותקן בלי
הלחיצה שלך.

לגיבוי: לפתוח את *My Media Backup* בטלפון ← **להפעיל מצב גיבוי**. המחשב מוצא אותו ו-
מתחבר; לאחר הגיבוי הטלפון מכבה את מצב הגיבוי בעצמו (וגם אחרי 5 דקות
ללא שימוש). האפליקציה יכולה רק לקרוא תמונות וסרטונים; החיבור מוצפן (TLS, התעודה
ננעצת בזמן ההתאמה). המחשב **מושך** את הקבצים: הוא מבקש כל קובץ, והטלפון עונה רק
למחשב המותאם ולעולם לא שולח דבר מעצמו. אותם קבצים ונתיבים כמו דרך ADB, כך שגיבויים קיימים פשוט ממשיכים.

## גיבוי דרך Wi-Fi (ללא כבל)

משתמש ב-**ניפוי באגים אלחוטי** המובנה של Android‏ (Android 11 ומעלה, בלי אפליקציה בטלפון). הכול
עובד כמו דרך USB, כולל בדיקת ה-SHA-256 בטלפון; זה רק איטי יותר (תלוי ב-
Wi-Fi, בדרך כלל 10–40 MB/s).

1. טלפון: *הגדרות ← מערכת ← אפשרויות למפתחים ← ניפוי באגים אלחוטי* ← להפעיל (לאפשר אותו עבור
   הרשת).
2. אפליקציה: **התאמה דרך Wi-Fi…** ← בטלפון להקיש *התאמת מכשיר באמצעות קוד QR* ולסרוק את הקוד
   (או להשתמש ב-*התאמת מכשיר באמצעות קוד התאמה* ולהקליד את 6 הספרות). נחוץ פעם אחת בלבד.
3. מאותו רגע הטלפון נמצא אוטומטית בכל פעם שניפוי הבאגים האלחוטי מופעל והטלפון וה-
   מחשב נמצאים באותה רשת Wi-Fi. אם גם USB וגם Wi-Fi זמינים, נעשה שימוש ב-USB.

**אין נתב? Wi-Fi ישיר:** **Wi-Fi ישיר…** מאפשר למחשב לפתוח רשת Wi-Fi משלו
(Linux: נקודה חמה של NetworkManager, 5 GHz אם אפשר; Windows: פותח את הגדרות
*נקודה חמה לנייד*). הטלפון מצטרף אליה (קוד QR למצלמה), והגיבוי רץ ישירות בין
הטלפון למחשב. רוב מתאמי ה-Wi-Fi מתנתקים בינתיים מה-Wi-Fi הרגיל; הוא חוזר כש-
ה-Wi-Fi הישיר נעצר (האפליקציה שואלת כשסוגרים אותה).

Wi-Fi Direct אמיתי (P2P) היה דורש אפליקציה נלווית בטלפון; הוא מתוכנן כשלב מאוחר יותר.

## תוכנית גיבוי לכל כונן

ברשימת הכוננים של *גיבוי חדש* לכל כונן גיבוי יש **תוכנית גיבוי**:

* **פשוט** – תיקייה אחת שגדלה, נוספות רק תמונות וסרטונים חדשים (כפי שמוצג למעלה).
* **סב-אב-בן** – גיבויים מתוארכים כמו באחסון משני (ראו בהמשך): גיבוי **מלא**
  כל 3 חודשים, גיבוי **דיפרנציאלי** כל חודש, גיבויים **אינקרמנטליים** ביניהם.
  גיבוי מלא/דיפרנציאלי מכיל גם את הקבצים הקודמים שהוא צריך (מועתקים בכונן
  ומאומתים), כך שתמונות שנמחקו מהטלפון נשארות בכל גיבוי מלא.

אפשר לשלב בין השניים, למשל *פשוט* בכונן HDD אחד ו-*סב-אב-בן* בשני. תיקיית
טלפון שומרת על התוכנית שאיתה התחילה.

## אחסון משני (ייצוא)

*ניהול גיבויים ← אחסון משני* מעתיק גיבוי לכונן אחר או ל-Google Drive. כל ייצוא
מקבל תיקייה משלו:

```
PhoneBackups-Export/Sam/Pixel 10 Pro/
├── 2026-11-02_14-30-00_full/            (with the export report in Logs/)
├── 2026-11-20_09-12-45_incremental/
├── 2026-12-01_18-03-10_differential/
└── .phonebackup-export/catalog.sqlite
```

| סוג           | מה מועתק                                           |
|---------------|----------------------------------------------------|
| full (מלא)          | הכול                                         |
| differential (דיפרנציאלי)  | כל מה שחדש מאז הייצוא ה**מלא** האחרון      |
| incremental (אינקרמנטלי)   | כל מה שחדש מאז הייצוא **האחרון** (מכל סוג) |

**אוטומטי – סב-אב-בן** (ברירת מחדל) בוחר את הסוג: מלא כל 3 חודשים
(סב), דיפרנציאלי כל חודש (אב), אינקרמנטלי ביניהם (בן); האפליקציה מציגה
מה מגיע בפעם הבאה ולמה. היא שומרת את 4 הייצואים המלאים, 3 הדיפרנציאליים ו-6 האינקרמנטליים
החדשים ביותר, וכן את כל מה שהם צריכים לשחזור; ייצואים ישנים יותר מוצעים להסרה ונמחקים
**רק אחרי אישורך** (*ניקוי ייצואים ישנים…*).

כל קובץ מיוצא נבדק מול ה-SHA-256 שנרשם בזמן הגיבוי. קובץ שנפגם
בכונן הראשון (bit rot) מדווח כ"אזהרה".
*שחזור* בונה מחדש תיקייה שלמה אחת מהשרשרת הקצרה ביותר (מלא + הדיפרנציאלי החדש ביותר +
האינקרמנטליים שאחריו) ומאמת כל קובץ.

### Google Drive

*הוספה לאחסון בענן ← Google Drive* מתחבר דרך הדפדפן. האפליקציה רשאית לראות רק את
הקבצים שהיא העלתה בעצמה (ההרשאה `drive.file` של Google); ההתחברות נשארת במחשב הזה.
שני סוגי ייצוא:

* **עותק** – שיקוף של הגיבוי ב-*My Drive/My Smartphone Media Backup/טלפון - בעלים*:
  מועלים רק קבצים חדשים, שום דבר לא נמחק או נדרס.
* **סב-אב-בן** ב-*טלפון - בעלים (סב-אב-בן)*: כל תמונה נשמרת
  **פעם אחת** בלבד – ייצואים מלאים ודיפרנציאליים מקשרים לקבצים שכבר נמצאים ב-Google Drive
  (קיצורי דרך, בלי מקום נוסף; גם לעותק). הניקוי מעביר קבצים שייצואים חדשים יותר עדיין
  משתמשים בהם אל תוכם לפני שמשהו נמחק. השחזור מוריד את הקבצים ומאמת אותם. נא
  לא למחוק שם תמונות בודדות ידנית – כל ייצוא שמקשר אליהן יאבד אותן.

כל העלאה נבדקת מול ה-SHA-256 של Google עצמה; המקום הפנוי נבדק לפני ההעלאה.
מדיניות פרטיות: <https://machetso.github.io/my-smartphone-media-backup/privacy.html>

בנייה מקוד המקור דורשת את מפתח ה-Google של האפליקציה: `python3 tools/set_google_key.py client_secret_….json`
(כותב את `phonebackup/_gkey.py` שמוחרג מ-git); גרסאות release מקבלות אותו מ-GitHub secrets.

## הגדרות

נשמרות ב-`~/.config/phonebackup/config.json` (Windows: `%APPDATA%\PhoneBackup\config.json`):
שם הבעלים, תיקיות הטלפון (ברירת מחדל `DCIM/Camera`, ניתן לבחור עוד בתוכנה),
כוננים, נתיב adb.

## בדיקות

```
python3 -m unittest discover tests
```

## נבדק

* Linux (Pop!_OS) עם Google Pixel 10 Pro (Android 17) דרך ADB ב-USB 3:
  1372 קבצים / 20 GB גובו לשני כונני HDD חיצוניים בו-זמנית ואומתו, כ-24 MB/s.
* Samsung Galaxy S20 FE דרך USB (ADB) ודרך Wi-Fi עם אפליקציית הטלפון 0.3.3:
  12.4 MB/s דרך Wi-Fi, ללא שגיאות; עדכון אפליקציית הטלפון דרך הכבל עם שאלת ההתקנה.
* Google Drive: עותק וסב-אב-בן עם גיבוי של 20 GB (1381 קבצים, כ-
  4 MB/s העלאה), קיצורי דרך, ניקוי ושחזור אומתו.
* עדיין לא נבדק על חומרה אמיתית: הגיבוי החלופי דרך MTP (Linux gvfs, Windows Explorer) ו-Windows באופן כללי.
